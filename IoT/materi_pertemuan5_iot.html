Fokus Pertemuan 5 adalah penggunaan fungsi, variabel, konstanta, serial monitor, debugging sintaks, dan debugging logika. Aktivitas utamanya adalah membaca error kompilasi, menambahkan Serial.print() untuk debugging, serta memecah program besar menjadi fungsi-fungsi kecil. Target minimumnya adalah Anda tidak hanya menyalin kode, tetapi mampu melacak kesalahan dan membuat program lebih rapi.

1. Mengapa Struktur Program yang Rapi Itu Penting?

Pada tahap awal belajar pemrograman mikrokontroler, banyak program masih ditulis dengan gaya “asal jalan”. Selama lampu menyala atau sensor terbaca, program dianggap selesai. Masalahnya, saat program mulai bertambah panjang, pendekatan seperti ini membuat kode sulit dibaca, sulit diperbaiki, dan sulit dikembangkan. Oleh karena itu, pertemuan ini menekankan bahwa program yang baik bukan hanya program yang berjalan, tetapi juga program yang terstruktur, mudah dipahami, dan mudah ditelusuri saat terjadi kesalahan.

Analogi dunia nyata: bayangkan sebuah gudang tanpa rak dan label. Semua barang memang ada di dalam gudang, tetapi ketika satu barang dicari, prosesnya menjadi lama dan membingungkan. Program yang berantakan mirip seperti itu. Sebaliknya, program yang rapi seperti gudang dengan rak, label, dan jalur kerja yang jelas: siapa pun lebih mudah memahami isinya dan lebih cepat menemukan masalah.

1.1 Ciri program yang rapi

Nama jelas
Variabel dan fungsi diberi nama yang menggambarkan perannya.
Tugas terpisah
Setiap fungsi mengerjakan satu tugas tertentu, tidak semua dicampur dalam loop().
Mudah diuji
Bagian-bagian program bisa dicek satu per satu saat terjadi kesalahan.

1.2 Dampak program yang tidak rapi

Program yang terlalu padat dalam satu blok sering menimbulkan tiga masalah. Pertama, pembaca sulit memahami alur. Kedua, kesalahan kecil sulit ditemukan karena semua logika bercampur. Ketiga, perubahan satu bagian bisa merusak bagian lain secara tidak sengaja. Dalam konteks IoT, masalah ini berbahaya karena program sering harus membaca input, mengontrol output, menampilkan log, dan nanti mengirim data ke jaringan secara bersamaan.

2. Fungsi, Variabel, dan Konstanta

Pertemuan 5 menempatkan fungsi, variabel, dan konstanta sebagai inti perapian program. Ketiganya terlihat sederhana, tetapi sangat menentukan kualitas kode.

2.1 Variabel

Variabel adalah tempat menyimpan data yang nilainya bisa berubah selama program berjalan. Contoh: status LED, nilai sensor, atau mode kerja. Variabel penting karena mikrokontroler perlu menyimpan hasil pembacaan atau kondisi terkini agar dapat mengambil keputusan.

Analogi dunia nyata: variabel seperti papan tulis kecil di meja kerja. Isi tulisannya bisa diubah kapan saja sesuai keadaan terbaru.

2.2 Konstanta

Konstanta adalah data yang nilainya tetap dan tidak diubah selama program berjalan, misalnya nomor pin atau ambang batas yang memang sengaja dibuat tetap. Konstanta membuat program lebih aman dan lebih mudah dibaca karena bagian yang bersifat tetap diberi penanda yang jelas.

Analogi dunia nyata: konstanta seperti nomor ruang kelas. Nomor itu dipakai terus sebagai acuan dan tidak berubah-ubah setiap beberapa menit.

2.3 Fungsi

Fungsi adalah blok program yang dibuat untuk menjalankan tugas tertentu. Dengan fungsi, program panjang bisa dibagi menjadi bagian-bagian kecil yang masing-masing punya peran jelas, misalnya membaca tombol, mengatur LED, atau menampilkan log ke serial monitor.

Analogi dunia nyata: fungsi seperti pembagian tugas dalam sebuah tim. Ada anggota yang khusus menerima data, ada yang memproses, dan ada yang melaporkan hasil. Pekerjaan menjadi lebih tertata dibanding semua orang mengerjakan semuanya sekaligus.

3. Serial Monitor sebagai Alat Debugging

Serial Monitor adalah salah satu alat paling dasar namun paling penting dalam pemrograman embedded. Dengan Serial Monitor, program dapat “berbicara” kepada pembuatnya: menampilkan pesan, nilai variabel, status proses, atau titik tertentu yang sedang dilalui program.

Pada pertemuan ini Anda diminta menambahkan Serial.print() untuk debugging. Tujuannya bukan sekadar mencetak teks, tetapi membangun kebiasaan melacak apa yang sebenarnya terjadi di dalam program.

Analogi dunia nyata: Serial Monitor seperti CCTV dan buku log di ruang kontrol. Tanpa keduanya, seseorang hanya menebak-nebak apa yang terjadi. Dengan log yang jelas, proses bisa dilihat langkah demi langkah.

3.1 Mengapa Serial Monitor berguna?

  • Menunjukkan apakah program benar-benar masuk ke bagian tertentu.
  • Menampilkan nilai variabel saat program berjalan.
  • Membantu membedakan apakah masalah terjadi pada pembacaan input, proses logika, atau output.
  • Mengurangi kebiasaan menebak-nebak penyebab error.

3.2 Contoh penggunaan dasar

Serial.begin(115200);
Serial.println("Program dimulai");
Serial.print("Nilai tombol: ");
Serial.println(buttonState);

Serial.begin(115200) mengaktifkan komunikasi serial dengan kecepatan tertentu. Setelah itu, Serial.println() dan Serial.print() dapat dipakai untuk menampilkan teks atau nilai variabel. Perbedaan utamanya adalah println menambahkan pindah baris, sedangkan print tidak.

4. Debugging: Error Sintaks dan Error Logika

Checkpoint pertemuan ini menekankan bahwa Anda harus dapat membedakan error sintaks dan error logika. Keduanya sering tertukar, padahal sifat dan cara menanganinya berbeda.

Jenis ErrorCiriContohCara menanganinya
Error sintaks Program gagal dikompilasi karena aturan penulisan salah. Titik koma hilang, kurung tidak seimbang, nama fungsi salah tulis. Baca pesan kompilasi, temukan baris terkait, lalu perbaiki penulisan.
Error logika Program berhasil dikompilasi, tetapi hasilnya tidak sesuai harapan. LED seharusnya menyala saat tombol ditekan, tetapi justru mati. Gunakan Serial Monitor, cek nilai variabel, telusuri alur keputusan program.

4.1 Contoh error sintaks

void setup() {
  Serial.begin(115200)
}

Kode di atas tampak sederhana, tetapi ada titik koma yang hilang setelah Serial.begin(115200). Akibatnya, program tidak akan dikompilasi. Ini adalah contoh error sintaks: aturan penulisan bahasa tidak dipenuhi.

4.2 Contoh error logika

if (buttonState == HIGH) {
  digitalWrite(ledPin, LOW);
}

Secara sintaks, kode ini benar. Namun, jika niat program adalah menyalakan LED saat tombol ditekan, maka logikanya salah karena kondisi HIGH justru membuat LED mati. Error seperti ini hanya bisa dikenali dengan memahami tujuan program dan mengamati perilaku hasilnya.

5. Contoh Refactoring: Dari Program Berantakan Menjadi Modular

Salah satu aktivitas pertemuan ini adalah memecah program besar menjadi fungsi-fungsi kecil. Di bawah ini ditunjukkan contoh sederhana agar perbedaan antara kode yang menumpuk dan kode modular terlihat jelas.

5.1 Versi kurang rapi

const int ledPin = 2;
const int buttonPin = 4;
int buttonState = 0;

void setup() {
  pinMode(ledPin, OUTPUT);
  pinMode(buttonPin, INPUT);
  Serial.begin(115200);
}

void loop() {
  buttonState = digitalRead(buttonPin);
  Serial.print("Button: ");
  Serial.println(buttonState);
  if (buttonState == HIGH) {
    digitalWrite(ledPin, HIGH);
  } else {
    digitalWrite(ledPin, LOW);
  }
  delay(200);
}

Program ini sebenarnya masih bisa dipahami, tetapi semua tugas masih menumpuk di loop(): membaca tombol, menampilkan log, dan mengatur LED. Ketika program nanti berkembang, loop() akan menjadi terlalu padat.

5.2 Versi lebih modular

const int ledPin = 2;
const int buttonPin = 4;
int buttonState = 0;

void setupPins() {
  pinMode(ledPin, OUTPUT);
  pinMode(buttonPin, INPUT);
}

void readButton() {
  buttonState = digitalRead(buttonPin);
}

void printDebugInfo() {
  Serial.print("Button: ");
  Serial.println(buttonState);
}

void updateLed() {
  if (buttonState == HIGH) {
    digitalWrite(ledPin, HIGH);
  } else {
    digitalWrite(ledPin, LOW);
  }
}

void setup() {
  Serial.begin(115200);
  setupPins();
}

void loop() {
  readButton();
  printDebugInfo();
  updateLed();
  delay(200);
}

5.3 Mengapa versi kedua lebih baik?

  • Setiap fungsi memiliki tugas yang jelas.
  • Jika terjadi masalah pada pembacaan tombol, perhatian bisa langsung diarahkan ke readButton().
  • Jika log terlalu banyak atau ingin diubah formatnya, cukup ubah printDebugInfo().
  • Program lebih mudah dibaca karena alur besar pada loop() sekarang tampak ringkas: baca input, tampilkan log, ubah output.
Analogi dunia nyata: versi modular seperti dapur restoran dengan stasiun kerja terpisah: ada bagian persiapan, bagian memasak, dan bagian penyajian. Jika ada masalah rasa, koki tidak perlu membongkar seluruh dapur; cukup memeriksa stasiun yang relevan.

6. Penjelasan Kode Secara Terperinci

Berikut penjelasan rinci pada versi modular agar hubungan antara teori dan implementasi menjadi jelas.

Dengan susunan seperti ini, Anda dapat melihat bahwa “program rapi” bukan sekadar masalah estetika penulisan. Kerapian langsung memengaruhi kemampuan untuk memahami, menguji, dan memperbaiki sistem.

Seluruh praktik pertemuan ini dikerjakan di simulator Wokwi, alat yang sama seperti pada pertemuan sebelumnya, sehingga tidak ada perangkat fisik yang perlu disiapkan. Bagian 7.1 memasang rangkaian yang dipakai bersama oleh semua latihan pada materi ini, bagian 7.2 menunjukkan tempat pesan kesalahan dan keluaran Serial Monitor dibaca, lalu bagian 7.3 dan 7.4 memakai keduanya untuk menelusuri kesalahan. 7.1 Menyiapkan rangkaian dan lingkungan kerja di simulator

Satu rangkaian saja sudah cukup untuk seluruh latihan pada materi ini. Rangkaian itu memuat tiga komponen yang memang muncul di contoh kodenya: LED pada ledPin, tombol pada buttonPin atau tombolPin, dan modul LDR pada ldrPin. Dengan ketiganya terpasang sejak awal, Anda dapat berpindah antara kode Bab 5.2, Program A, dan Program B tanpa merakit ulang apa pun.

Komponen yang perlu ditambahkan: satu LED, satu resistor bernilai 220 Ω, satu tombol atau pushbutton, dan satu modul LDR sebagai sensor cahaya. Semuanya diambil dari daftar komponen yang terbuka ketika tanda tambah (+) pada panel rangkaian ditekan.

Urutan sambungannya terbagi menjadi empat kelompok. Pertama, GPIO 2 → resistor 220 Ω → kaki panjang LED, lalu kaki pendek LED → GND. Kedua, satu kaki tombol → GPIO 4 dan kaki di seberangnya → GND; kaki yang dipakai harus dua kaki yang berseberangan, karena dua kaki pada sisi yang sama sudah tersambung di dalam tombol. Ketiga, pin AO modul LDR → GPIO 34. Keempat, pin VCC modul LDR → 3V3 dan pin GND modul LDR → GND. Nomor pin ini bukan pilihan bebas: 2 dan 4 diambil dari ledPin dan buttonPin pada Bab 5.1 serta Bab 5.2, sedangkan 34 diambil dari ldrPin pada Program A di Bab 10.1. GPIO 34 juga tidak dapat ditukar dengan sembarang pin, karena pembacaan analog pada ESP32 hanya tersedia pada GPIO 32 sampai 39 dan pin tersebut hanya dapat menjadi input.

Bila panel rangkaian menjadi kosong setelah tempelan itu dimasukkan, biasanya ada tanda kurung atau koma yang ikut terhapus. Tempelkan ulang seluruh isinya, jangan hanya sebagian.

  1. Buka wokwi.com di browser, pilih New Project, lalu pilih board ESP32.
  2. Kenali empat bagian pada layar: panel kode di sisi kiri berisi berkas sketch.ino, panel rangkaian di sisi kanan, tab diagram.json di atas panel rangkaian, dan tombol jalankan berbentuk segitiga hijau.
  3. Pasang keempat komponen seperti gambar di atas, atau tempelkan diagram.json yang tersedia. Untuk menyambung dua kaki komponen, klik kaki pertama lalu klik kaki kedua.
  4. Hapus seluruh isi panel kode, lalu tempelkan contoh kode dari Bab 5.2. Kode itu dipakai lebih dahulu justru karena isinya sudah benar, sehingga Anda mengenal tampilan program yang berjalan normal sebelum berhadapan dengan program yang rusak.
  5. Periksa bahwa angka pada const int ledPin = 2; dan const int buttonPin = 4; sama dengan nomor pin yang benar-benar tersambung di panel rangkaian.
  6. Tekan tombol jalankan, lalu amati dua tempat sekaligus: LED di panel rangkaian dan tulisan yang muncul di jendela Serial Monitor di bagian bawah layar.
  7. Sebagai variasi, hentikan simulasi lalu ubah delay(200) pada baris terakhir loop() menjadi delay(1000), jalankan kembali, dan bandingkan kecepatan munculnya baris baru di Serial Monitor dengan pengamatan sebelumnya.

Hasil yang harus terlihat: Serial Monitor menampilkan baris Button: 0 atau Button: 1 yang bertambah kira-kira lima baris setiap detik, dan LED di panel rangkaian mengikuti angka itu: menyala ketika angkanya 1 dan mati ketika angkanya 0. Setelah nilai delay diubah menjadi 1000, baris baru hanya muncul kira-kira satu kali setiap detik sehingga keluarannya jauh lebih mudah dibaca. Perbedaan ini perlu Anda alami sendiri, karena log yang mengalir terlalu cepat adalah salah satu penyebab utama penelusuran kesalahan menjadi sulit.

Project baru hanya berisi board. Area rangkaian pada project ESP32 yang baru dibuat masih kosong: belum ada LED, resistor, tombol, maupun modul LDR di sana. Bila kode dijalankan pada project yang masih kosong, pin GPIO 2 tetap berganti keadaan dan Serial Monitor tetap mencetak angka, tetapi tidak ada apa pun yang terlihat menyala, sehingga kode yang sebenarnya sudah benar mudah dikira salah. Karena itu rangkaian selalu dipasang lebih dahulu, sebelum kode dijalankan.
Bila angka di belakang Button: berubah sendiri tanpa tombol ditekan. Contoh kode pada Bab 5.1 dan Bab 5.2 memakai pinMode(buttonPin, INPUT) tanpa pull-up, sehingga GPIO 4 tidak memiliki nilai yang pasti selama tombol tidak ditekan dan angkanya dapat berpindah-pindah sendiri. Ini bukan kerusakan rangkaian, melainkan gejala yang khas dan justru berguna sebagai bahan latihan membaca log. Bila Anda ingin pembacaannya stabil, ganti menjadi INPUT_PULLUP seperti pada Program B di Bab 10.1. Ingat bahwa dengan pull-up kondisi tertekan terbaca LOW, sehingga perbandingan di dalam updateLed() perlu dibalik agar LED tetap menyala saat tombol ditekan.

7.2 Membaca pesan kesalahan dan membuka Serial Monitor

Dua hal pada bagian ini adalah bekal yang dipakai di seluruh sisa materi: mengetahui di panel mana pesan kompilasi muncul, dan mengetahui di mana keluaran Serial.print() dibaca. Tanpa keduanya, langkah-langkah pada Bab 7.3 tidak dapat dijalankan karena tidak ada tempat untuk melihat hasilnya. Kerjakan langkah berikut memakai Program A pada Bab 10.1, yang memang sengaja memuat satu kesalahan sintaks, di atas rangkaian yang baru Anda pasang.

  1. Ganti seluruh isi panel kode dengan Program A dari Bab 10.1, lalu tekan tombol jalankan. Kompilasi akan gagal dan simulasi tidak akan dimulai.
  2. Cari pesannya pada panel pesan yang terbuka di bagian bawah panel kode. Panel itu baru muncul ketika kompilasi gagal, dan isinya adalah keluaran kompiler apa adanya, bukan terjemahannya.
  3. Baca satu baris pesan dari kiri ke kanan. Bentuknya sketch.ino:12:3: error: expected ';' before '}' token: bagian pertama adalah nama berkas, angka pertama sesudah nama berkas adalah nomor baris, angka kedua adalah nomor kolom pada baris itu, lalu kata error diikuti keterangan masalahnya.
  4. Cocokkan nomor baris tersebut dengan nomor yang tercetak di tepi kiri panel kode. Menekan pesannya biasanya langsung memindahkan kursor ke baris yang dimaksud, dan baris itu juga ditandai di panel kode.
  5. Periksa juga baris di atas baris yang disebut, jangan hanya baris itu sendiri. Nomor baris pada pesan menunjukkan tempat kompiler menyadari ada masalah, dan tempat itu tidak selalu sama dengan tempat kesalahan ditulis. Pada Program A, pesannya dapat menunjuk baris }, padahal titik koma yang hilang ada di baris di atasnya.
  6. Perbaiki kesalahannya, jalankan kembali, lalu pastikan panel pesan tadi tidak muncul lagi. Selama panel itu masih muncul, tidak ada satu baris pun program yang benar-benar dijalankan.
  7. Setelah kompilasi berhasil, buka jendela Serial Monitor di bagian bawah layar dengan menekan judul panel bernama Serial Monitor. Jendela itu dapat diperlebar dengan menarik tepi atasnya ke atas, sehingga lebih banyak baris keluaran terlihat sekaligus.
  8. Pastikan baris Program A siap muncul di sana, lalu perhatikan baris Nilai cahaya: yang menyusul. Bila jendela itu tetap kosong padahal kompilasi berhasil, periksa bahwa Serial.begin(115200); benar-benar ada di dalam setup().
  9. Geser penggeser tingkat cahaya pada gambar modul LDR, lalu perhatikan angka pada baris Nilai cahaya: ikut berubah dan LED menyala ketika angka itu turun di bawah nilai ambangGelap, yaitu 1500.

Hasil yang harus terlihat: sebelum perbaikan, panel pesan di bawah panel kode memuat satu baris error yang menyebut nama berkas beserta nomor baris, sedangkan Serial Monitor sama sekali kosong. Sesudah perbaikan, panel pesan itu hilang, Serial Monitor menampilkan Program A siap disusul angka Nilai cahaya: yang bertambah satu baris setiap setengah detik, dan LED menyala atau mati mengikuti nilai tersebut. Kedua keadaan itu perlu Anda lihat berurutan, karena perbandingan di antara keduanyalah yang membuat perbedaan antara gagal dikompilasi dan berjalan tetapi salah hasilnya menjadi konkret.

Perubahan kode tidak berlaku pada simulasi yang sedang berjalan. Setiap kali panel kode disunting, hentikan simulasi lalu jalankan kembali agar kode yang baru ikut dikompilasi. Bila langkah ini terlewat, perbaikan yang sudah benar tampak seperti tidak berpengaruh, dan Anda mudah mencurigai bagian program yang sebenarnya tidak bermasalah.

7.3 Langkah debugging yang sistematis

  1. Jalankan kompilasi. Jika gagal, baca pesan error dan identifikasi jenis kesalahannya.
  2. Perbaiki error sintaks terlebih dahulu. Selama program belum bisa dijalankan, error logika belum bisa diuji.
  3. Tambahkan Serial Monitor. Cetak nilai variabel penting atau pesan di titik tertentu.
  4. Uji satu bagian dalam satu waktu. Misalnya, pastikan pembacaan tombol benar sebelum memeriksa LED.
  5. Rapikan setelah program benar. Gunakan fungsi kecil agar pemeriksaan berikutnya lebih mudah.

7.4 Contoh skenario

Misalnya LED tidak menyala saat tombol ditekan. Jangan langsung mengganti semua baris. Pertama, cek apakah program bisa dikompilasi. Kedua, tampilkan nilai tombol ke Serial Monitor. Jika nilai tombol ternyata selalu 0, masalah ada pada pembacaan input atau wiring virtual. Jika nilai berubah dengan benar, baru cek bagian logika LED. Dengan pendekatan ini, debugging menjadi proses terarah, bukan coba-coba acak.

Analogi dunia nyata: debugging seperti mencari penyebab lampu ruangan tidak menyala. Seseorang tidak langsung membongkar seluruh instalasi gedung. Ia mulai dari hal paling dasar: apakah saklar ditekan, apakah bohlam masih baik, apakah listrik tersedia, lalu bergerak ke kemungkinan yang lebih spesifik.

8. Ringkasan Materi

  • Program yang rapi memudahkan pembacaan, pengembangan, dan perbaikan.
  • Variabel menyimpan data yang berubah, konstanta menyimpan acuan tetap, dan fungsi membagi tugas program menjadi bagian yang jelas.
  • Serial Monitor adalah alat penting untuk memahami apa yang terjadi di dalam program.
  • Error sintaks membuat program gagal dikompilasi, sedangkan error logika membuat hasil program salah meskipun kompilasi berhasil.
  • Program modular lebih mudah diuji dan lebih mudah di-debug dibanding program yang seluruh logikanya bercampur dalam satu blok besar.

Materi Pertemuan 5 ini berfokus pada penggunaan fungsi, variabel, konstanta, serial monitor, debugging sintaks, dan debugging logika; dengan aktivitas membaca error kompilasi, menambahkan Serial.print(), dan memecah program besar menjadi fungsi-fungsi kecil.

10. Tugas Latihan Pertemuan 5

Tugas latihan pertemuan ini terdiri atas dua bagian. Bagian pertama melatih kemampuan menemukan kesalahan pada program yang sudah ada, dan bagian kedua melatih kemampuan merapikan program yang sebenarnya sudah berjalan. Keduanya saling melengkapi: kesalahan lebih mudah ditemukan pada program yang tersusun rapi, dan program hanya dapat dirapikan dengan benar bila Anda memahami cara kerjanya.

10.1 Tugas 1: perbaiki dua program rusak

Di bawah ini terdapat dua program, dan masing-masing memuat tepat satu kesalahan. Program A memuat satu kesalahan sintaks, sedangkan Program B memuat satu kesalahan logika. Salin keduanya ke simulator, jalankan, temukan kesalahannya, lalu perbaiki. Kerjakan lebih dahulu tanpa membuka kunci jawaban pada Bab 10.4, karena nilai latihan ini justru ada pada proses pencariannya.

Komponen yang perlu ditambahkan: tidak ada. Kedua program dijalankan di atas rangkaian gabungan yang sudah dipasang pada Bab 7.1, karena rangkaian itu memuat LED pada GPIO 2, tombol pada GPIO 4, dan modul LDR pada GPIO 34, yaitu seluruh pin yang dipakai Program A dan Program B. Tempat pesan kompilasi dibaca dan cara membuka jendela Serial Monitor dijelaskan pada Bab 7.2.

Program A. Program ini dimaksudkan untuk menyalakan LED ketika ruangan gelap. Sensor cahaya dipasang sedemikian sehingga nilai pembacaan yang makin kecil berarti ruangan makin gelap, dan ambang batasnya ditetapkan pada 1500. Selain satu kesalahan yang sengaja ditanam, seluruh bagian lain sudah benar.

// Program A: LED indikator ruangan gelap
const int ldrPin = 34;
const int ledPin = 2;
const int ambangGelap = 1500;

int nilaiCahaya = 0;

void setup() {
  Serial.begin(115200);
  pinMode(ledPin, OUTPUT);
  Serial.println("Program A siap");
}

void bacaCahaya() {
  nilaiCahaya = analogRead(ldrPin)
}

void tampilkanLog() {
  Serial.print("Nilai cahaya: ");
  Serial.println(nilaiCahaya);
}

void aturLed() {
  if (nilaiCahaya < ambangGelap) {
    digitalWrite(ledPin, HIGH);
  } else {
    digitalWrite(ledPin, LOW);
  }
}

void loop() {
  bacaCahaya();
  tampilkanLog();
  aturLed();
  delay(500);
}

Program B. Program ini dimaksudkan untuk menghitung berapa kali tombol ditekan, lalu menampilkan jumlahnya ke Serial Monitor. Tombol dipasang dengan INPUT_PULLUP, sehingga kondisi tertekan terbaca sebagai LOW. LED menyala selama tombol ditekan, dan bagian itu sudah benar. Program ini berhasil dikompilasi tanpa pesan error, tetapi hasil hitungannya tidak seperti yang diharapkan.

// Program B: penghitung jumlah tekanan tombol
const int tombolPin = 4;
const int ledPin = 2;

int kondisiTombol = HIGH;
int kondisiSebelumnya = HIGH;

void setup() {
  Serial.begin(115200);
  pinMode(tombolPin, INPUT_PULLUP);
  pinMode(ledPin, OUTPUT);
  Serial.println("Program B siap");
}

void loop() {
  int jumlahTekan = 0;

  kondisiTombol = digitalRead(tombolPin);

  if (kondisiSebelumnya == HIGH && kondisiTombol == LOW) {
    jumlahTekan = jumlahTekan + 1;
    Serial.print("Jumlah tekan: ");
    Serial.println(jumlahTekan);
  }

  if (kondisiTombol == LOW) {
    digitalWrite(ledPin, HIGH);
  } else {
    digitalWrite(ledPin, LOW);
  }

  kondisiSebelumnya = kondisiTombol;
  delay(50);
}

Yang dikumpulkan untuk Tugas 1 adalah kode kedua program yang sudah diperbaiki, disertai catatan singkat untuk masing-masing program: baris mana yang salah, jenis kesalahannya, gejala yang Anda lihat sebelum perbaikan, dan apa yang Anda ubah. Untuk Program B, sertakan juga tangkapan layar Serial Monitor sebelum dan sesudah perbaikan sebagai bukti bahwa perilakunya memang berubah.

10.2 Tugas 2: rapikan satu program dari pertemuan sebelumnya

Pilih satu program yang sudah pernah Anda buat pada pertemuan sebelumnya, lalu susun ulang menjadi versi yang lebih modular. Beberapa pilihan yang cocok:

  • Program tombol dan LED atau pola blinking dari Pertemuan 2.
  • Program smart light berbasis ambang batas dari Pertemuan 3.
  • Program portal otomatis dengan servo dan buzzer dari Pertemuan 4.

Ketentuan pengerjaannya sebagai berikut:

  1. Buat minimal tiga fungsi selain setup() dan loop().
  2. Setiap fungsi hanya mengerjakan satu pekerjaan, misalnya menyiapkan pin, membaca input, menampilkan log, atau mengatur keluaran.
  3. Nama fungsi harus menjelaskan pekerjaannya sehingga isinya dapat diduga tanpa dibuka, misalnya bacaSensor(), tampilkanLog(), atau aturAktuator(). Nama seperti fungsi1() tidak diterima.
  4. Setelah dirapikan, loop() sebaiknya hanya berisi urutan pemanggilan fungsi, sebagaimana bentuk pada Bab 5.2.
  5. Perilaku program tidak boleh berubah. Versi rapi harus memberi hasil yang sama dengan versi sebelumnya.

Sertakan penjelasan singkat, tiga sampai lima kalimat, tentang alasan Anda memecah program seperti itu: pekerjaan apa yang dipisahkan, dan bagian mana yang kini lebih mudah diperiksa bila terjadi kesalahan. Bab 5.3 dan tabel pada Bab 6 dapat dipakai sebagai contoh cara menjelaskan hubungan antara nama fungsi dan tugasnya.

Yang dikumpulkan untuk Tugas 2 adalah kode versi sebelum dan versi sesudah dirapikan, ditambah penjelasan singkat tersebut.

10.4 Kunci jawaban

Bagian ini dibaca setelah Anda mencoba sendiri. Membaca kunci lebih dahulu memang lebih cepat, tetapi kemampuan yang diuji pada checkpoint adalah menemukan kesalahan tanpa bantuan, bukan mengenali kesalahan yang sudah ditunjukkan.

Program A, kesalahan sintaks. Baris yang salah adalah nilaiCahaya = analogRead(ldrPin) di dalam fungsi bacaCahaya(). Baris itu tidak diakhiri titik koma, padahal setiap pernyataan harus ditutup dengan titik koma. Tanpa tanda itu, kompiler menganggap pernyataan belum selesai dan terus membaca sampai menemukan kurung kurawal penutup.

Gejalanya: program gagal dikompilasi, sehingga tidak ada yang berjalan dan Serial Monitor tetap kosong. Pesan kompilasi yang muncul berbunyi seperti expected ';' before '}' token. Kompiler menyebut tanda } sebagai bagian yang ditemuinya, padahal yang sebenarnya kurang adalah titik koma pada baris di atasnya. Penanda posisinya bisa berada di ujung baris nilaiCahaya = analogRead(ldrPin) atau pada baris } sesudahnya, tergantung versi kompiler. Inilah kebiasaan yang perlu dibangun sejak awal: pesan error menunjukkan tempat kompiler menyadari ada masalah, dan tempat itu tidak selalu sama dengan tempat kesalahan ditulis. Perbaikannya cukup menambahkan titik koma.

void bacaCahaya() {
  nilaiCahaya = analogRead(ldrPin);
}

Program B, kesalahan logika. Baris yang salah adalah int jumlahTekan = 0; yang ditulis di dalam loop(). Deklarasi di posisi itu membuat variabel dibuat ulang setiap kali loop() dijalankan, sehingga nilainya kembali menjadi 0 pada setiap putaran dan hasil penambahan tidak pernah menumpuk. Secara sintaks penulisannya sah, karena itu kompilasi berhasil dan tidak ada pesan error apa pun.

Gejalanya terlihat pada perilaku, bukan pada pesan kompilasi: LED tetap menyala dengan benar saat tombol ditekan, tetapi Serial Monitor selalu menampilkan Jumlah tekan: 1 berapa kali pun tombol ditekan. Angkanya tidak pernah menjadi 2 atau 3. Perbaikannya adalah memindahkan deklarasi keluar dari loop() sehingga menjadi variabel global bersama variabel lain di atas setup(), lalu menghapus baris deklarasi yang ada di dalam loop().

int kondisiTombol = HIGH;
int kondisiSebelumnya = HIGH;
int jumlahTekan = 0;

void loop() {
  kondisiTombol = digitalRead(tombolPin);
  // sisa isi loop() tetap sama, tanpa baris deklarasi jumlahTekan
}

Setelah diperbaiki, Serial Monitor akan menampilkan angka yang bertambah: 1, lalu 2, lalu 3, dan seterusnya. Cara lain yang juga benar adalah menulis static int jumlahTekan = 0; di dalam loop(), karena kata static membuat nilai variabel bertahan antarpemanggilan. Perhatikan urutan kerja pada kedua program ini: kesalahan Program A harus diperbaiki lebih dahulu agar program dapat berjalan, sedangkan kesalahan Program B hanya dapat ditemukan setelah program berjalan dan perilakunya diamati, persis seperti langkah debugging pada Bab 7.3.
